# 风机音频异常检测（L1 baseline）

风力发电机轮毂气传导音频，30 s 一段，判断正常/异常并把异常定位到秒级区间。

## 两级结构

| | 做什么 | 在哪训练 | 现状 |
|---|---|---|---|
| **L1** | 正常 vs 异常（含工况变化），高召回，定位 | 本地 Mac | 已实现 baseline，等正常数据 |
| **L2** | 真故障 vs 正常工况变化（阵风/启停/偏航/雨噪） | 服务器 GPU，人工复核数据迭代 | 本地不做；报告先导出事件特征 |

L1 只学“正常长什么样”。异常标注**不参与训练**，只用于定阈值、算召回/误报。这样没见过的故障也能报出来。

## 快速开始

```bash
cd wind_audio

# 看文件信息
python3 -m wind_audio probe --input data/anomaly/A01_01_20261030_120227.wav

# 没有正常数据时：用异常文件的安静段做演示拟合（仅验证链路）
python3 -m wind_audio run \
  --input data/anomaly/A01_01_20261030_120227.wav \
  --demo --threshold 8 --out outputs/A01_01_demo

# 有正常数据后：训练 + 推理
python3 -m wind_audio train --normal-dir data/normal --out models/l1_v0 --threshold 5
python3 -m wind_audio run --input data/normal/xxx.wav --model models/l1_v0 --out outputs/xxx
```

每次运行输出：

```
outputs/<name>/
  report.html      # 时频图 + 分数曲线 + 事件表（给人看）
  spectrogram.png  # 时频图，绿框为报警事件
  score.png        # 帧级异常分数 + 阈值
  events.json      # 事件 + 特征（给 L2 / 数据库）
  events.csv       # 同上，Excel 可直接打开
```

## L1 方法（v0）

- 44.1 kHz / 单声道，30 s；STFT `n_fft=2048`、`hop=441`（10 ms 帧移）。
- 128 维 log-mel，20–16 kHz。
- 正常模型：每个 mel 频带学 median + MAD；帧分数 = `0.5×平均|z| + 0.5×top10%|z|`，再做 0.15 s 中值平滑。
  - 平均项抓宽带爆发；top-k 项抓窄带异常。
- 事件提取：双阈值滞回（高阈值进入、0.6×阈值退出）+ 合并 0.3 s 内间隔 + 最短 0.2 s。
- 事件特征：时长、峰值/均值 z、频谱质心、平坦度、峰值频率、谐波度、5 个频带占比、起始斜率。
  这些就是 L2 的输入。

## 数据要求

**正常样本（L1 训练）**

- 起步：20–30 段 30 s，覆盖不同时间/机组/风速。
- 算误报率：20–40 小时。
- 同一台风机不同季节、不同转速都要有；否则“正常”学窄了。

**异常样本（只做阈值校准和评估）**

- 全部提供，越多越好；最好带秒级起止。
- 起步：5–10 段；要比较有把握地说“95% 召回”，测试集至少 50–60 个独立异常事件。
- 标注 CSV：`file,label,fault_type,start_s,end_s,note`。

**优先给原始长录音**（几小时连续），我来切 30 s。固定切好的 30 s 会丢上下文，也不好做事件级评估。

**划分**：测试集按“机组 + 时间段”分，不能随机切 30 s 窗口——相邻窗口泄漏会让指标虚高。

## 评估口径

- **事件级召回**：报警区间与标注区间有重叠（或中心落在容差内）即命中。
- **误报**：每小时误报次数（FA/h），不是帧级准确率。
- **延迟**：从异常起始到首次报警的时间。
- 阈值按“验证集召回 95%”定，再看测试集 FA/h；两个数一起报，不能只报召回。

## L2（服务器端，下一步）

本地不训练 L2，但接口已经留好：`events.csv` 的每行就是一个事件样本。

- **输入**：事件特征（时长、质心、平坦度、频带占比、起始斜率、谐波度）+ 事件波形 embedding。
- **标签**：人工复核 → `fault` / `condition_change`；类型体系可扩展（现在二分类，结构留多类）。
- **增量学习**：回放缓冲（每类保留代表样本）+ 新数据微调，避免只学新类、旧类退化。
- **版本与回滚**：每次训练保存“权重 + 预处理版本 + 阈值 + 指标”；新模型先影子评估，达标才切流量；保留上一版，一键回滚。
- **评估**：旧类每类召回不退化、新类召回、误报率，三项一起看。

## 已知限制

- 当前 `l1_demo` 是**演示模型**：只用异常文件的安静段拟合，阈值未用正常数据校准，不能用于生产判断。
- 没有 SCADA。工况只能从声音反推（总声压级、频谱质心、约 0.3 Hz 的转子调制）。风机变转速会让频谱整体搬移，正式模型需要按工况分层或做转速归一化。
- 该文件 50 Hz 工频及谐波很强，会掩盖低频故障特征；是否陷波要先用多文件确认它是否稳定。
- L1 目前对**绝对电平/增益**敏感：合成测试里，比真实背景低 30 dB 的正常音频会让整段 30 s 被报成异常。同一传感器、同一增益下问题不大；跨机组/跨传感器部署前，需要加“每文件电平对齐”或增益无关特征。
- L2 本地不训练，符合“服务器上迭代”的设计；当前只导出事件特征。
