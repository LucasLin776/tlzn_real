# L1 v3：多尺度稳定性检测

本文件记录 `spectral_stability_v3` 的业务前提、算法、参数、评估口径与实测结果。
旧版 `spectral_event_v2` 的实现和 `config/l1.json` 保持不变，可随时复现历史结果。

## 1. 业务定义 → 设计映射

| 业务定义 | 实现 |
|---|---|
| 观察时间内频谱基本稳定即正常，不限形状/频率/响度 | 稳定度由**逐频带自身波动**与**局部噪声尺度**判断，不与任何固定音色、固定 dB 或整段最强声比较 |
| 正常允许小噪声与背景波动 | 每个频带有稳健噪声容差（局部 MAD × 系数，带上下限），超出才计入 |
| 超过容差的明显变化才算事件 | 触发需同时满足：加权变化 ≥ 3σ **且** 超容差频带比例 ≥ 15%，或单个短瞬态足够强/足够宽 |
| 工况切换可报警，重新稳定后必须结束并接受新背景 | 释放判据只看**当前是否稳定**，从不与事件前背景比较；确认后直接把新状态当作正常 |
| 连续短事件可合并，但不得跨过已恢复稳定的区间 | 状态机只在“稳定确认”后结束事件；短间隙不足以完成确认，事件自然合并 |
| 标注名称不影响正负标签 | 所有区间标注一律按异常真值处理；名称只做追溯 |
| 离线，检测不得读标签 | `l1-detect` 只接收音频与配置；`l1-test` 的标签仅用于评估 |

## 2. 算法结构

三层，全部无需训练，只使用本录音自身的稳健统计量：

### 2.1 逐帧指标（`wind_audio/stability.py`）

| 指标 | 单位 | 含义 |
|---|---|---|
| `sigma` | dB | 局部噪声尺度：快速差分（0.1 s）在 2 s 窗内的稳健 MAD，限幅 0.35–6 dB |
| `change_z` | 噪声σ | 归一化快速变化，能量加权 RMS；**不是 dB、不是概率** |
| `exceed` | 0–1 | 超过 `band_z`（默认 3σ）的频带比例，按 `power^0.25` 加权 |
| `slow_ratio` | 容差倍数 | 相邻 1 s 块的电平差 / 该频带**自身**慢变化的典型幅度，用于捕捉缓慢但累计明显的变化 |
| `fluct_frac` | 0–1 | 0.6 s 窗内波动仍在容差内的频带比例 |
| `drift_frac` | 0–1 | 0.4 s 均值漂移仍在容差内的频带比例 |
| `excess_ratio` | 0–1 | 当前电平偏离近 2 s 背景、且超过该偏差**自身**慢尺度波动的频带比例（用于保持尾部与释放） |
| `stable` | 布尔 | 波动、漂移均在容差内，且窗内无快速变化 |

要点：

- 统计量在 0.1 s 粗网格上计算后插值，兼顾速度与尾部稳定性。除两处离线前视（3 帧居中平滑 ≤20 ms、
  1 s 块均值在块内最多 1 s 前视）外，其余全部因果；产品是离线分析，不承诺流式实时性。
- **每个判据的容差都由被测量自身的波动尺度校准**，而不是统一用 0.1 s 快速差分的噪声：
  慢变化用该频带 1 s 块差在 20 s 内的稳健幅度，电平偏离用残差在 5 s 内的稳健幅度。
  这条规则消除了“快速差分很小、慢漂移很大”导致的报警不释放与低频误触发。
- 比最强频带低 30 dB 以上的频带不参与判定，避免静音频段的数值放大。
- 频带权重取 `power^0.25`：既不采用纯能量加权（会被低频风噪淹没中高频事件），也不采用纯计数（单个泄漏频点即可主导）。

### 2.2 事件状态机（`wind_audio/state.py`）

```
初始化 → 稳定 → 变化候选 → 事件活动 → 稳定确认 → 新稳定（接受新背景）
```

- **触发**：`change_z ≥ 3σ` 且 `exceed ≥ 15%` 连续 3 帧；或单帧 ≥ 4.5σ；或单帧 ≥ 2.4σ 且超容差频带 ≥ 30%；或慢变化持续 0.2 s。
- **起点**：触发后回退到“最后一个仍然平静的帧”，上限 0.6 s。
- **终止**：最近 0.8 s 内 ≥90% 帧处于“平静”（正式稳定，或变化与余量都远低于触发），**且**最近 0.2 s 完全没有触发证据；事件结束时间回溯到该确认窗的起点。
- **新背景**：结束后不保留任何旧参考，下一事件从当前状态重新开始。
- 没有固定最大时长；文件结束时仍未确认则标记 `right_censored`。
- 开头 0.5 s 只用于建立噪声基准；上下文不足（短文件）返回空结果并置 `context_insufficient`。

### 2.3 质量诊断

`stability.audio_quality` 计算削顶比例、波峰因数与 RMS，仅作诊断：不修改音频、不参与检测，
评估时按 clean / clipped 分组报告。削顶无法通过归一化恢复，因此不声称能修复。

## 3. 参数与调节方向

配置文件：`config/l1_v3.json`（`schema_version=2`）。命令行参数与配置同名（下划线→连字符）。

| 参数 | 默认 | 作用 | 调大 | 调小 |
|---|---:|---|---|---|
| `trigger_change_z` | 3.0 | 触发所需变化强度（σ） | 更保守，漏检增加 | 更敏感，误报增加 |
| `trigger_exceed` | 0.15 | 触发所需超容差频带比例 | 只保留宽带事件 | 少量频带变化即可触发 |
| `band_z` | 3.0 | 单频带“超容差”的门槛 | 噪声容忍更高 | 更敏感 |
| `sigma_floor_db` / `sigma_cap_db` | 0.35 / 6 | 快速噪声尺度上下限 | 下限抬高→安静段更保守 | 上限降低→强变化更难被归一化掉 |
| `slow_cal_s` / `slow_scale` / `slow_floor_db` / `slow_cap_db` | 20 s / 2 / 0.6 / 8 dB | 慢变化容差：20 s 内典型 1 s 变化的 2 倍，带上下限 | 更容忍慢变化（风摆不报警） | 更敏感于缓慢爬升 |
| `excess_cal_s` / `excess_scale` / `excess_floor_db` / `excess_cap_db` | 5 s / 3 / 0.8 / 12 dB | 电平偏离容差：5 s 内残差的 3 倍，带上下限 | 更难判定“已回到背景”，尾巴更长 | 更易释放 |
| `weight_exp` | 0.25 | 频带权重指数 | 更偏向强频带 | 0 = 按频带计数 |
| `active_range_db` | 30 | 参与判定的频带范围 | 纳入更弱的频带 | 只看主要频带 |
| `fast_s` / `noise_s` / `stable_s` / `drift_s` | 0.1 / 2 / 0.6 / 0.4 | 快变化、噪声、稳定、漂移的观察尺度（秒） | 更平滑、更慢 | 更灵敏、更抖 |
| `confirm_s` / `confirm_ratio` / `hold_s` | 0.8 / 0.9 / 0.2 | 稳定确认时长、比例与“无触发”保持时间 | 结束更慢、尾更长 | 结束更快，可能截断 |
| `slow_min_duration` | 0.5 | 仅由慢变化触发的事件最短时长 | 更少块边界伪事件 | 允许更短的慢事件 |
| `quiet_change_ratio` / `quiet_exceed_ratio` / `quiet_excess` | 0.5 / 0.5 / 0.2 | “没有明显变化”的判定 | 更容易结束 | 更严格，事件更长 |

调参建议顺序：先定 `band_z` 与 `sigma_*`（噪声容忍度），再定观察尺度
（`fast_s`、`noise_s`、`stable_s`），最后定 `confirm_s`/`trigger_*`。每次只动一个量级。

## 4. 评估口径

`l1-test` 同时输出三套口径（`evaluate.py`）：

1. **事件**：IoU ≥ 0.1 一对一贪心匹配（沿用旧口径，供历史对比）。
2. **时长**：预测窗口并集与已审核正常/异常区间的重叠秒数；未审核区不计分。
3. **拖尾**：每个真值事件结束后 3 s 内，仍在正常区报警的秒数；> 0.5 s 计为一次拖尾。
4. **事件簇**：真值与预测都按 **固定 0.5 s 间隔**合并（小于稳定确认时间，不会跨过已确认稳定的区间），
   再按 IoU ≥ 0.1 匹配；规则在验证前固定并写入 `metrics.json`。
5. **质量分组**：按削顶比例把录音分为 clean / clipped 分别报告。

结论（限定在这三批开发数据上）：

- **事件召回**三批均上升（+6.6 / +8.8 / +14.4 个百分点），B03、B04 的 F1 也上升。
- **最长窗口**从 21.4 / 17.4 / 20.1 s 降到 6.2 / 2.5 / 4.3 s，>3 s 窗口从 7/19/12 个降到 3/0/5 个；
  “工况改变后报警延续到文件末尾”的问题基本消失。
- **报警拖尾**：B02 22.9→12.9 s、B03 282→97 s、B04 48.8→40.7 s。
- **B02 的事件精确率**仍低于旧版（0.606 → 0.333），但**时长口径全面优于旧版**：
  时长准确率 0.982 vs 0.977、时长精确率 0.364 vs 0.309、覆盖率 0.624 vs 0.530。
  多出来的约 45 个短事件中，35 个是 2–16 kHz 对比 +2~4 dB 的弱瞬态（已标注事件中位 +5 dB），
  约 10 个是 20–300 Hz 的低频起伏（如 B02-091 的 +12.9 dB / 7.9 s）。
- **时长召回与覆盖率下降**不是回归：B03 标注对声学事件前后各扩了约 0.2 s，标注时长中位 0.62 s，
  而实测声学核心（任一频带高出背景 ≥3 dB）中位仅约 0.19 s。新版窗口贴近声学变化，
  旧版较长的窗口恰好更接近被扩张的旧标注。**这是口径冲突，按业务定义保留标注、不改算法去拟合。**

## 6. 已知限制

- 时间边界以 20 ms 网格输出，不等于真实边界精度；`padding` 默认为 0，不再人为扩张。
- 极安静且事件稀疏的录音（B02 类）误报偏高，需要现场确认“细小机械声”是否值得报警。
- 削顶录音（B04 中 37/95 条）动态范围被压缩，召回与边界精度下降；程序只做诊断，不做修复。
- 稳定定义依赖观察窗（默认 0.6–2 s）。若工况本身以更慢的周期漂移，需要增大 `noise_s`/`stable_s`。
- **窄带缓慢变化**：`slow_ratio` 取活跃频带的中位数，只有少数高频道带缓慢移动时会被判为不显著。
  B04-043（19.7 s 起 8–16 kHz 抬升约 8 dB）、B04-048（22 s 起 8–16 kHz 下降约 8 dB）属于这种情况：
  该频带比最强频带低约 38 dB，总能量占比很低，按“允许小噪声”的定义没有触发。
  若要捕捉这类事件，需要增加独立的窄带慢变化通道，不在本次改动范围内。
- 多声道、24 bit/浮点 WAV 仍不支持（沿用旧限制）。

```bash

cd /Users/shuoqinlin/Desktop/wind_audio

# 检测版：只有音频

  --config config/l1_v3.json --out runs/l1_v3/sample
```
