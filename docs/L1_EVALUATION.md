# L1 检验器：实现步骤与使用

## 1. L1、L2 分工

L1 使用局部频谱变化和事件持续活动规则，输出候选事件起止时间，无训练权重。
L2 使用候选窗口和原音频，通过冻结的 PANNs CNN14 提取特征，训练分类头判断异常类型。
本检验器只调用 L1，标签只用于比较，不参与特征计算、背景估计或参数拟合。
所有事件名称均作为 L1 二分类正例；类别名称只保留作追溯。

检测入口是 `l1-detect --input 原始音频路径`，只接受音频与检测配置，不接受标签。
测试入口是 `l1-test --audio-dir 音频目录 --labels 标签路径`，必须同时给出音频和标签。
二者共享同一检测算法；`run/evaluate` 分别保留为旧命令别名。
工作数据路径与运行示例见 [README 的两个入口](../README.md#l1-的两个入口)。

## 2. 已实现的步骤

1. **读取与配对**：`markers.py` 读取每条音频对应的 Name/Start/Duration 标注。
   默认按相同文件名匹配；显式 `--pairing sorted` 按自然排序配对并输出 `pairing.csv`。
   如 `0:10.877 + 0:00.624` 转为 `[10.877, 11.501]` 秒。
   简易 CSV/JSON 则由 `data.py:import_simple` 读取；已有标准清单可直接使用。
2. **校验标签**：从 WAV 读取时长和采样率，检查音频缺失、数量、时间越界、
   非有限时间、标签冲突、重复 ID；先校验再写标准清单与标注。
   仅声明完整审核时，将未标注部分及空标注文件当正常；否则为 unknown。
3. **运行 L1**：加载 `config/l1.json`，逐条读取原始音频，经 `extract_features`
   和 `SpectralChangeDetector.predict_events` 输出最终候选窗口。
   与 `l1-detect` 命令使用同一检测实现，不使用标签辅助检测，不做重新训练。
4. **比较文件**：出现任意候选窗口就预测整条音频“有事件”。
   与文件标签或精确区间推导的文件标签比较，记录 TP/TN/FP/FN。
5. **比较时间与事件**：合并预测窗口的重叠时长，按连续区间计算 TP/TN/FP/FN 秒数，
   不把短事件压到离散采样网格。事件使用按 IoU 从高到低的贪心一对一匹配，
   一个预测最多匹配一个真值；IoU 的预测时长排除 unknown。
6. **汇总与输出**：`evaluate.py` 计算文件、时长和事件指标，写 JSON、CSV 和中文简报。
   所有文件累加计数/时长后再计算准确率，不平均逐文件百分比；零分母输出 null。
   输出目录非空时拒绝覆盖；数据错误返回非零状态。
7. **对照图与 PDF**：同一次推理将波形、真实变化/活动分数与最终窗口交给 `eval_plots.py`，
   逐录音生成四联图；下方两图都是标签在上、预测在下，分别展示原始事件和短间隔合并后的事件簇。
   不重复运行模型，按音频 ID 自然顺序将图片编入 `comparison.pdf`，一条音频一页。
   事件簇仅供诊断，不修改原始标签、预测或指标；未审核区域灰底显示，粗标签不展开成区间。

## 3. B02 运行命令

```bash
conda activate post_training
cd /Users/shuoqinlin/Desktop/wind_audio
python -m wind_audio l1-test \
  --audio-dir /Users/shuoqinlin/Desktop/数据/B02/音频 \
  --labels /Users/shuoqinlin/Desktop/数据/B02/标注 \
  --pairing sorted \
  --assume-unlabeled-normal \
  --config /Users/shuoqinlin/Desktop/wind_audio/config/l1.json \
  --match-iou 0.1 \
  --out /Users/shuoqinlin/Desktop/输出结果/B02_visual_new
```

首次结果已保存于 `reports/l1_B02`；重跑使用新的输出目录。
图表参数：`--plot-merge-gap 0.3` 调整辅助事件簇间隔；`--plot-font` 指定中文字体；
`--no-plots` 关闭图片/PDF，仅输出数值。正常文件也生成一页，明确标示无标签事件或无预测事件。
原 B02 目录只读，不复制音频，不改标注。用户已确认：

- B02-001～100 对应按文件名时间从早到晚排序的 100 条音频。
- 所有文件完整审核，空标注和未标注部分均正常。
- “胶粒掉落”“启动”“异响”都算 L1 应检出的事件。

配对仅用于标签核对，不作为 L1 的输入特征。输出中的 source_id 只是录音标识，
100 个不同录音标识不代表 100 个独立设备；L2 来源划分不能直接据此宣称跨设备独立。

## 4. 其他标签格式

整段标签，CSV 或同字段的 JSON 数组：

```csv
file,label
normal.wav,normal
event.wav,anomaly
```

文件列可用相对路径；支持 normal/anomaly/uncertain、正常/异常、0/1。
没有起止时间时自动识别为文件级标签，只计算文件指标，不将整段展开为异常真值。

区间标签：

```csv
file,start_s,end_s,label
a.wav,1.2,1.8,anomaly
a.wav,4.0,4.5,uncertain
b.wav,0,30,normal
```

```bash
python -m wind_audio l1-test --audio-dir /path/to/audio \
  --labels /path/to/labels.csv --config config/l1.json --out reports/my_check
```

只有确实完整审核过全部文件，才添加 `--assume-unlabeled-normal`。
明确标为 uncertain 的区间始终排除。局部正常标签不能证明整条音频正常；
局部已确认事件足以证明整条音频存在事件。

标准 `manifest.csv + annotations.csv` 格式见 [标注规范](ANNOTATION.md)。
已有固定独立集合可使用 `--splits /path/to/splits.json --split test`，否则评估全部文件。

## 5. 指标定义

正例表示“有事件/处于事件时间段”，负例表示“正常”。

| 口径 | 定义 | 适用范围 |
|---|---|---|
| 文件准确率 | `(TP + TN) / 已知标签文件数` | 整段是否报警；不检查事件位置 |
| 文件召回率 | `TP / (TP + FN)` | 带事件文件中出现告警的比例 |
| 文件精确率 | `TP / (TP + FP)` | 告警文件中确实带事件的比例 |
| 时长准确率 | `(TP秒 + TN秒) / 已审核秒数` | 预测与标签在时间轴上的一致比例 |
| 异常时长召回率 | `TP秒 / (TP秒 + FN秒)` | 所有预测窗口覆盖的真实异常时长比例 |
| 时长精确率 | `TP秒 / (TP秒 + FP秒)` | 报警时长中真正异常的比例 |
| 事件召回率 | `匹配数 / 真值事件数` | 按 IoU 门槛一对一匹配 |
| 事件精确率 | `匹配数 / 涉及已审核区的预测数` | 同上 |
| F1 | `2PR / (P + R)` | 文件、时长、事件分别计算 |
| 平衡准确率 | `(正例召回率 + 负例召回率) / 2` | 缺少任一类别时为 null |

默认 IoU ≥ 0.1 较宽松，可用 `--match-iou 0.5` 指定更严格门槛；不同门槛不能直接比较。
`coverage` 是一对一匹配成功的窗口覆盖比例，`time_metrics.recall` 是全部预测窗口的
时间并集覆盖比例，二者不同。每小时误报只计未匹配且触及正常区的预测，
分母为已审核正常小时数。正常区误报时长还包含已匹配窗口的多余部分。

## 6. B02 默认配置结果（2026-11-04）

100 条录音，共 3000.272 秒；11 条带事件，89 条正常；30 个真值事件，总异常时长 34.657 秒。
参数固定为当前 `config/l1.json`，未使用 B02 调阈值。

- 文件准确率 **96.00%**，TP=11、TN=85、FP=4、FN=0。
- 文件召回率 **100.00%**，精确率 **73.33%**，F1 **0.8462**。
- 文件误报：**B02-061、B02-075、B02-086、B02-096**。
- 时长准确率 **97.71%**；异常时长召回率 **79.18%**，时长精确率 **30.90%**。
- 时长混淆：TP=27.443 秒，TN=2904.240 秒，FP=61.375 秒，FN=7.214 秒。
- 33 个候选窗口中匹配 20 个真值事件；事件召回 **66.67%**、精确率 **60.61%**、F1 **0.6349**。

文件级 100% 召回不表示 30 个事件全部正确定位。未匹配的 10 个真值包含漏检、
边界不满足 IoU 或多个真值合并成一个候选等情况，需按 `events.csv` 逐项检查。
正常时长占约 98.84%，全预测正常也会得到约 98.84% 的时长准确率，因此不能只看准确率。
当前模型更需要关注异常覆盖和窗口过宽造成的误报时长。

## 7. 输出文件

| 文件 | 内容 |
|---|---|
| `brief.md` | 中文结果摘要 |
| `metrics.json` | 总体指标、逐文件指标、实际参数、输入标签、预测窗口、IoU 匹配明细 |
| `per_file.csv` | 每条录音的真值、预测、混淆结果和时间统计 |
| `events.csv` | 预测/真值窗口、匹配索引、IoU；索引从 0 开始 |
| `manifest.csv` / `annotations.csv` | 导入后的标准输入快照；直接用已有清单时不重复生成 |
| `pairing.csv` | 标注目录与原音频路径的明确对应关系 |
| `plots/*.png` | 每条音频的波形、分数、上下行区间对比图 |
| `plots/index.csv` | 页码、音频 ID、原音频路径、图片路径 |
| `comparison.pdf` | 所有对照图按音频 ID 自然顺序汇总，每条一页，含音频书签 |

文件级 TP 不能证明告警发生在正确时间；区间级结果提供这个核对依据。
指标不使用标签类别区分，不依赖 L2 权重。

## 8. v3（`spectral_stability_v3`）检验口径

v3 与 v2 共用同一个 `l1-test` 入口和同一套数据校验，但分数语义不同：

| 输出 | 单位 | 说明 |
|---|---|---|
| `change_z` | 局部噪声 σ | 归一化快速变化，不是 dB、不是概率 |
| `exceed` | 0–1 | 超过单频带容差的频带比例 |
| `stable_frac` | 0–1 | 波动与漂移都在容差内的频带比例 |
| `state` | 0/1/2 | 初始化 / 稳定 / 事件活动 |
| `stable` | 布尔 | 与事件结束判据一致 |

除旧的事件与时长指标外，v3 额外输出：

1. **报警拖尾**：每个真值事件结束后 3 秒内、仍在已审核正常区报警的秒数；
   超过 0.5 秒计为一次拖尾（`trailing_alarm_s`、`n_trailing`）。
2. **事件簇**：真值与预测都按固定 0.5 秒间隔合并后再一对一匹配（`cluster_*`）。
   0.5 秒小于稳定确认时间，因此不会跨过已确认稳定的正常区间；规则在验证前固定并写入 `metrics.json`。
3. **质量分组**：按削顶比例分为 clean / clipped 分别报告（`quality_groups`），
   削顶只做诊断，不修改原始波形。

v3 的边界回溯意味着：事件结束时间是“稳定确认窗的起点”，而不是确认完成的那一刻；
因此拖尾指标应与事件边界一起看。若标注本身包含稳定后的过渡段（例如 B03 中标注比声学核心宽约 0.2 秒），
覆盖率与时长召回会低于事件召回——这属于标注口径冲突，应记录而不是改算法去拟合。
